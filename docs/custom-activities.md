# Custom activities (MVP)

- Tokyo picks includes three independent custom slots. Search is button-triggered, not autocomplete. Drafts stay separate and continuing is blocked until unfinished inputs are saved or cleared.
- `POST /api/groups/:code/activities/search` requires the device's existing group credential and same-origin protection. Requests are limited to 30 per member/hour, 120 uncached site-wide/hour and one shared call per 1.1 seconds.
- Provider: Photon public demo (`https://photon.komoot.io/api/`), GeoJSON / OpenStreetMap. Documentation: https://github.com/komoot/photon/blob/master/docs/api-v1.md. Search covers bbox minLon/minLat/maxLon/maxLat = `138.5,34.8,141,36.5`, with Tokyo bias and English-preferred names. This deliberately excludes distant trips and is not an event or booking inventory search. Public service availability is not guaranteed.
- Only the query is sent externally. No profile, nickname, access credential or manual description is forwarded to Photon. Avoid private queries/addresses. A bounded response produces up to three unique valid public OSM IDs, addresses and WGS84 point references. Empty or failed queries never generate synthetic results.
- Candidates must be explicitly confirmed by the user. Query date and provider are retained. Confirmation verifies neither actual hours, entrances, an event's existence, ticket availability nor reservations. If no candidate fits, the user supplies timing, location and description, explicitly marked unverified.
- Search results are cached six hours under a SHA-256 query key. Raw query text is not stored in that cache. Candidate receipts are cached 24 hours using OSM ID + original query date; original query dates never reset on cache hits. Save checks the candidate against a server receipt or that member's unchanged previously saved match; tampered coordinates/name/address or expired new receipts are rejected.
- `trip_members.custom_activities` is nullable JSON, added by migration 0003. Old profiles default to an empty list; all old answers are retained. Custom details follow existing member privacy: only self and organizer, not other members. Group deletion cascades to custom profiles. Saving any changed profile invalidates an old plan via its revision.
- Up to three custom entries, and at most three must-visits **combined** across listed/custom places. A custom must-visit can be #1. Organizer summary preserves attribution. Confirmed and manual activities are both sent to DeepSeek under anonymous traveler labels, with explicit untrusted-data and factual-boundary instructions.
- Generation uses `customActivityId` to attribute custom stops and flags unscheduled custom must-visits deterministically in review notes. A description or identity match does not guarantee feasibility. Existing meal-area anchors remain; incompatible custom requests need organizer review. Custom stop map pins / routing are deliberately not implemented: no catalog pin may be guessed for these stops, including low-walking alternatives.
- Verification: `node --test tests/*.test.mjs`; `node scripts/smoke-shared-groups.mjs <origin> --custom --styles --evidence` (one disposable group, removed afterwards). Adding `--generate` makes one real LLM call. Browser QA covers confirming Tokyo Tower in slot 3 while preserving a slot 1 draft, manual workshop details, setting a custom #1, submission and organizer summary.
